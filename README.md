# Трёхуровневая информационная система для PyCharm

Клиент HTML/JavaScript → сервер Flask → база данных SQLite.
Гейнрих Владислав Николаевич, группа ОКБИ-302 Б.

## Запуск

1. Распакуй архив. Открой **папку `three_layer_pycharm`** в PyCharm через **File → Open**.
2. Выбери интерпретатор Python 3.10 или новее. Можно создать виртуальное окружение `.venv` для проекта.
3. Открой вкладку **Terminal** внизу PyCharm. Выполни из папки проекта:

   ```bash
   python -m pip install -r requirements.txt
   ```

4. Открой `app.py`, нажми правой кнопкой в редакторе и выбери **Run 'app'**.
5. Открой в браузере **http://127.0.0.1:8000**. Сервер должен продолжать работать в PyCharm.

Из терминала можно запустить так:

```bash
python app.py
```

Если порт занят, останови предыдущий запуск или используй другой порт:

```bash
python app.py --port 8001
```

Тогда адрес сайта — http://127.0.0.1:8001.
Если появляется `ModuleNotFoundError: flask`, установи зависимости именно для интерпретатора выбранного проекта.

## Что работает

- Просмотр, добавление, изменение и удаление пользователей.
- Поиск по имени и email, включая русские имена без учёта регистра.
- Проверка имени/email и запрет повторяющегося email.
- Подтверждение удаления.
- Экспорт CSV и скачивание согласованной резервной копии SQLite.
- Просмотр последнего API-запроса и SQL в раскрывающемся блоке на сайте.

База находится в **`data/users.db`** и сохраняет записи после остановки сервера и перезапуска PyCharm.
При первом запуске в новой базе создаются три демонстрационных пользователя с адресами `example.com`.
В архив включена такая демонстрационная база. Это не копия пользовательских записей из твоей запущенной среды Colab.

## Перенос записей из Colab

1. В предыдущем блокноте нажми на сайте **Скачать базу .db**.
2. Останови `app.py` в PyCharm.
3. Сохрани скачанный файл **вне папки `data`**, например в папке «Загрузки».
4. В терминале проекта выполни, заменив путь своим:

   ```bash
   python restore_db.py "C:/Users/Имя/Downloads/users.db"
   ```

5. Запусти `app.py` снова. Скрипт проверяет копию и переносит её записи одной транзакцией.
   Перед заменой текущие записи сохраняются в `data/users_before_restore.db`.

## Файлы и три уровня

| Файл | Назначение |
|---|---|
| `app.py` | Точка запуска сервера, путь базы и порт |
| `templates/index.html` | Клиент: форма и таблица |
| `static/style.css` | Клиент: оформление и адаптация к телефону |
| `static/app.js` | Клиент: кнопки и HTTP-запросы `fetch` |
| `server.py` | Сервер: Flask, REST API и проверка входных данных |
| `database.py` | Данные: подключение, SQL, транзакции и резервные копии |
| `data/users.db` | Файл базы SQLite |
| `restore_db.py` | Перенос данных из сохранённой копии |
| `requirements.txt` | Зависимости Python |

Пример: клиент отправляет POST `/api/users` с JSON → Flask проверяет поля →
SQLite выполняет параметризованный INSERT → Flask возвращает HTTP 201 с ID →
JavaScript обновляет таблицу. Браузер не обращается к SQLite напрямую.

| Метод и адрес | Назначение |
|---|---|
| GET `/api/users?q=текст` | Список и поиск |
| GET `/api/users/ID` | Одна запись |
| POST `/api/users` | Добавление |
| PUT `/api/users/ID` | Изменение |
| DELETE `/api/users/ID` | Удаление |
| GET `/api/health` | Проверка сервера и базы |
| GET `/api/backup` | Копия SQLite |
| GET `/api/export` | CSV |

Сайт открывается локально на твоём компьютере; постоянный хостинг ему не требуется.
